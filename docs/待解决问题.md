## 1. 数据库相关

### 【问题 1】MySQL root 密码硬编码于 server/.env
- **章节/文件**：server/.env
- **问题描述**：DATABASE_URL 中包含明文密码 `root:482023@localhost`，不适合生产环境
- **当前临时方案**：开发阶段直接写入 .env，server/.env 已加入 .gitignore 不会被提交
- **后续优化建议**：部署到服务器时通过环境变量注入密码，使用 `DATABASE_URL=${MYSQL_URL}` 占位

### 【问题 2】Prisma Schema 与 seed.ts 中 categories 表的 id 不可自增
- **章节/文件**：server/prisma/schema.prisma → Category model
- **问题描述**：PRD §6.2 规定分类 ID 为 1-8 的固定值，但 Prisma 默认 @default(autoincrement()) 会从 1 开始自增。seed 脚本中使用 upsert 手动指定 id=1~8
- **当前临时方案**：Category model 不设 @default(autoincrement())，seed 脚本手动指定 id
- **后续优化建议**：保持当前方案——分类 ID 被评估工具的权重矩阵引用，不可变更

### 【问题 3】seed.ts 只插入 86 条权重记录而非 480 条
- **章节/文件**：server/prisma/seed.ts、src/data/assessment-weights.ts
- **问题描述**：简化版权重矩阵（方案 A）只插入了 weight>0 的 ~112 条记录。数据库中没有 weight=0 的显式行
- **当前临时方案**：matching.ts 中 `wMap.get(`${k}_${d}`) || 0` 兜底处理缺失权重，效果等价
- **后续优化建议**：V2 升级为完整权重矩阵时，seed 脚本应补全 480 行

## 2. 前端路由和状态

### 【问题 4】ThresholdPage 路由复用导致状态混淆
- **章节/文件**：src/App.tsx、src/pages/ThresholdPage.tsx
- **问题描述**：`/tools/threshold` 和 `/tools/threshold/result` 共用同一个 ThresholdPage 组件，通过 `useLocation` 判断路径来切换 stage。这导致从 result 页面点击"重新评估"后，URL 不变化
- **当前临时方案**：sessionStorage 传递结果数据，组件内部判断 location.pathname 切换状态
- **后续优化建议**：拆分为独立路由组件 ThresholdPage 和 ThresholdResultPage，后者直接从 sessionStorage 读取

### 【问题 5】AssessmentPage 的 beforeunload 提示在部分浏览器中可能不生效
- **章节/文件**：src/pages/AssessmentPage.tsx
- **问题描述**：现代浏览器对 beforeunload 事件施加了严格限制——必须用户有过交互（click、input）才展示对话框。纯键盘操作或无交互的页面刷新可能不触发
- **当前临时方案**：标准 addEventListener 方式已实现，符合浏览器基本要求
- **后续优化建议**：V2 引入 Zustand persist 中间件自动存 localStorage，彻底解决数据丢失问题

## 4. 安全和性能

### 【问题 8】未实现请求限流
- **章节/文件**：server/src/index.ts
- **问题描述**：PRD §11.5 要求"限流"，但 V1 未引入 @fastify/rate-limit 等限流中间件
- **当前临时方案**：V1 用户量极小（仅内部测试），暂不引入限流
- **后续优化建议**：公测前通过 `npm install @fastify/rate-limit` 添加，全局 100 req/min

### 【问题 9】未实现防重复提交（幂等）
- **章节/文件**：server/src/routes/tools.ts → POST /api/tools/assessment/evaluate
- **问题描述**：用户快速点击"提交评估"两次会触发两次 POST 并可能写入两条结果
- **当前临时方案**：前端按钮点击后立即设置 `disabled` + `setStage("calculating")`，阻止重复点击。但无法防止用户绕过前端直接调 API
- **后续优化建议**：V2 引入基于 userId+timestamp 的幂等键（idempotency key）

### 【问题 10】前端 chunk 文件 645KB 较大
- **章节/文件**：vite.config.ts
- **问题描述**：首次加载的 JS bundle 约 645KB（gzip 后 186KB），主要来自 recharts 图表库（约 300KB）
- **当前临时方案**：接受 V1 的加载体积，不影响本地开发体验
- **后续优化建议**：将 recharts 用 dynamic import() 按需加载（仅三个工具页面需要图表），预计减少 40%
